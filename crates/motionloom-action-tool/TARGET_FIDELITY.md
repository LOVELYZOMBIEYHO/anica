# Target-bound Action fidelity: implementation and acceptance

Status: joint-motion fidelity pipeline implemented and independently certified;
contact/skin visual acceptance remains separate. This is not a pixel-identical
pipeline. No MotionLoom runtime, DSL parser, schema or WASM changes are part of
the animation conversion. MotionLoom only gained an additive, read-only
experimental joint-matrix diagnostic API, shared by native and WASM verification;
existing APIs, playback behavior and DSL syntax remain unchanged. Blender is not
launched by the native backend.

## Implemented

- Read the exact target GLB rest hierarchy and existing `ModelProfile` / retarget
  / axis calibration declarations; reject duplicate or missing required mappings.
- Evaluate source hierarchy transforms, including intermediate unmapped nodes.
  Convert source-world bases for both displacement and rotation.
- Align anatomical child directions between source and target rest poses,
  preserving target bind twist. Reject ambiguous antiparallel calibration.
- Retarget global rotations, then solve overrides through the target parent and
  bind transforms. Preserve target bone lengths.
- Transform hips displacement into the target pelvis-local frame. Do not apply
  source world displacement directly as a local pelvis translation.
- Match the existing runtime's additive rest Euler calibration and transform
  composition; subtract calibration once before encoding Action channels.
- Emit existing semantic channels where available, plus raw residual rotation
  channels where required. Unwrap Euler angles across full rotations.
- Adaptively insert subframes; round-trip the serialized DSL through the existing
  parser and compare tool-side reconstructed positions and rotations.
- Record SHA-256 hashes for source, target, profile and Action; write atomically
  and protect input paths. Strict failure preserves existing Action files.
- Audit target model-global feet, toes, hands, head and hips at 120 Hz. This is
  joint-centre trajectory evidence only; it never inserts contacts or claims skin
  clearance, collider contact or foot locking.
- Add synthetic, independently calculated same-rig pelvis and knee expectations,
  rest alignment, full-turn, calibration, path-safety and failure-gate tests.

## What the report does and does not prove

`tool_reconstruction_pass` measures whether serialized Action channels reproduce
the tool's calculated target pose within thresholds at evaluated subframes. It
does **not** prove that the native importer matches an independent FBX evaluator,
that the target calibration is anatomically exact, or that native/WASM playback
matches the tool. Sharing transform mathematics can hide shared mistakes.

The converter writes source and native evidence. WASM evidence is generated by a
separate Node/WASM runner and combined only when Action, target and World hashes
match. `strict_pass` means all three comparisons and tool reconstruction passed;
it does not include skin deformation or physical contact quality.

The reference grid samples intervals, not every continuous time. Skin deformation,
twist distribution, floor contact and mesh intersection are not included in the
reported joint reconstruction metric.

## Local Stand To Roll candidate (2026-08-27)

- Source: user-supplied `Stand To Roll.fbx`, source animation clip, 2.366667 seconds.
- Target: Character1 and `character1_profile`, normalized height 1.82 m.
- Starting samples: 72 at 30 fps; fidelity candidate: 334 poses.
- Source vs independent ufbx: approximately 0.0014 mm / 0.0001°.
- Target/native reconstruction: approximately 0.872 mm / 0.097°.
- Native/WASM: 285 snapshots and 19,095 joints; maximum matrix element difference approximately 2.62e-7.
- The read-only trajectory audit exposes below-ground joint centres during the
  roll candidate. This correctly keeps contact/skin acceptance separate from the
  passing joint-matrix fidelity certificate.
- Fidelity output uses subframe times. `--time-grid milliseconds` has no duplicate
  editor keys but measured approximately 0.804 mm / 0.211° and fails the 0.1° gate.
- Earlier native GPU snapshots at frames 0, 18, 35, 55 and 71 used a reduced
  selected-pose preview. They remain isolated renderer smoke checks, not visual
  acceptance of the current 334-pose candidate.
- Landing Page's default Action was **not replaced**. Do not publish this candidate
  as an editable, fidelity-verified default.

The report and candidate remain local under `temp-save-3d-action`; the third-party
source is not added to redistributable test fixtures.

## Remaining work before accepting the complete plan

1. Independent source reference: completed with ufbx evaluation at 120 Hz. The
   legacy reader matched authored keys but not FBX interpolation, so production
   conversion now uses the evaluator.
2. Full target calibration: use explicit reference poses to resolve twist, forked
   chains and terminal joints. Direction alignment alone cannot determine these.
3. Editor-safe fidelity: solve time quantization and spatial error-bounded key
   reduction together. Do not simply merge colliding poses or claim 30 fps output
   with the tighter adaptive error bound.
4. Contact adaptation: trajectory auditing is implemented. Add a separate,
   opt-in offline correction pass for changed
   proportions, pelvis and foot/hand/roll contacts. Keep the uncorrected candidate
   available; changing contact for a different rig is not exact source replication.
5. Runtime comparison: completed for model-global Action joints through a new
   additive read-only API and hash-bound WASM runner. No FBX support entered
   MotionLoom. Scene contact, constraints and skin deformation remain excluded.
6. Final acceptance: validate the complete clip, compare representative rendered
   poses and contact phases, check editor import/export, then promote the library
   preset only after these checks pass.

Until this is resolved, target mode rejects changing scale, non-hips translation,
unsupported affine transforms, missing glTF cubic tangents, automatic contacts
and legacy channel reduction instead of silently discarding those semantics.

Different skeletal proportions and skin weights prevent a universal promise of
pixel-identical reproduction. Acceptance should separately state same-rig motion
fidelity and different-rig contact/visual quality.

## Verification commands

```sh
cargo test -p motionloom-action-tool
cargo clippy -p motionloom-action-tool --no-deps -- -D warnings
cargo check -p motionloom --target wasm32-unknown-unknown
```

These checks establish importer regression coverage and build isolation. They do
not substitute for the missing source-reference and runtime fidelity checks.
